EMDataset Documentation

Overview

The EMDataset class is an abstract dataset class designed for deep learning tasks in the context of Electron Microscopy (EM) data. It extends PyTorch's Dataset and provides a structured approach for:

  • Data Loading: Handles loading raw data from specified file paths.
  • Annotation Loading: Assumes raw data is paired with relevant metadata or annotations, defined by annotations_dir.
  • Preprocessing: Enables data preparation steps like denoising or contrast enhancement, which are saved to disk for supervision by EM specialists.
  • Postprocessing: Provides a mechanism for reconstructing results (e.g., stitching predictions from patches into a full image).

This class defines the structure and workflow for handling datasets, but specific behaviors (like loading data or implementing postprocessing logic) must be customized by subclassing.

Attributes

  • logger: A logging object to handle messages and status updates during preprocessing.
  • data_paths: A list of file paths to the raw or preprocessed data.
  • annotations_dir: Directory to annotations.
  • transform: An optional callable to apply transformations on the data.

Logger Class Documentation

Introduction

The Logger class is designed to simplify the process of logging various aspects of model training and evaluation. It ensures that the relevant information is saved in a structured format, which can later be reviewed to monitor training progress and results. This class requires minimal setup and can be easily extended to suit specific needs.

Within our template, we provide a simple logger that does not require additional setup for electron microscopy (EM) specialists. The logger creates a folder at ./logs/current-datetime/ to store logs.

Key Features

The logger automatically saves the following information in its log directory:

  • Used hyperparameters (in hyperparameters.json)
  • The best performing model checkpoint (based on validation loss)
  • Training and validation loss curves (in training_curves.png)
  • Qualitative visualizations of sampled validation images
  • Test metrics (in test_metrics.json)
  • Qualitative visualizations of sampled test images

The logger also supports resource usage logging, including CPU, RAM, and GPU memory usage.

Class Overview

The Logger class provides a set of methods to log different aspects of the training process. Here’s an overview of the key methods available:

  • __init__(): Initializes the logger, creates directories for logs, and sets up logging configuration.
  • log_info(message): Logs an informational message to both stdout and the log file.
  • log_warning(message): Logs a warning message to both stdout and the log file.
  • log_error(message): Logs an error message to stderr and the log file.
  • log_hyperparameters(hyperparams): Saves hyperparameters to a JSON file.
  • save_checkpoint(model, val_loss, epoch): Saves the best-performing model checkpoint based on validation loss.
  • plot_training_curves(train_loss, val_loss): Plots and saves training and validation loss curves.
  • log_test_metrics(metrics): Logs test metrics to a JSON file.
  • get_resource_usage(): Logs system resource usage including CPU, RAM, and GPU memory (if available).
  • log_resource_usage(): Saves the resource usage information to a log file.
  • save_sample_images(**kwargs): A placeholder method to save qualitative visualizations of sampled images (requires implementation by the DL specialist).

def plot_training_curves(self, train_loss, val_loss):
    plt.figure()
    plt.plot(train_loss, label="Train Loss")
    plt.plot(val_loss, label="Validation Loss")
    plt.xlabel("Epoch")
    plt.ylabel("Loss")
    plt.legend()
    plt.title("Training and Validation Loss")
    
    plot_path = os.path.join(self.plots_dir, "training_curves.png")
    plt.savefig(plot_path)
    plt.close()
    self.log_info(f"Training curves saved to {plot_path}")

Extending the Logger

The logger class can be extended to include additional logging functionality. If you decide to use external tools for logging, please provide detailed documentation to ensure that the EM specialists can understand how to use the logging system effectively.

To extend the logger, modify the src/Logger.py file and implement new logging methods as needed.
