DEEP-EM TOOLBOX:

Deep Learning Toolbox for Electron Microscopy Researchers

Hannah Kniesel1, Tristan Payer1, Poonam Poonam1, Tim Bergner2, Pedro Hermosilla3 Timo Ropinski1,
1Visual Computing Group, Ulm University
2Central Facility for Electron Microscopy, Ulm University
3Computer Vision Lab, TU Vienna
Paper

Despite advancements in CV, the application of Deep Learning (DL) in Electron Microscopy (EM) labs remains limited. We believe this is due to the interdisciplinary nature of EM, where expertise in data collection and annotation resides in EM labs, while expertise in model development and evaluation methods lies within DL labs.

To bridge this gap, we introduce the DEEP-EM TOOLBOX, disentangling the complexities of DL for EM. The toolbox provides a simple workflow for implementing DL solutions, separating low-level training details from high-level execution. This enables EM experts to train their own models while allowing DL experts to implement training and evaluation methods with minimal overhead.

Specialized solutions within the toolbox facilitate the training of lab-specific models by categorizing use cases into tasks based on model input/output. We showcase one example use case for each task, designed to be easily adaptable within EM labs.

The toolbox also encourages contributions from the research community. By following the provided workflow, these contributions become accessible to both the DL and EM communities, fostering collaboration.

The DEEP-EM TOOLBOX includes a dedicated webpage featuring the paper's main objectives, getting-started tutorials, detailed documentation for each use case, and guidance on contributing original work.

Main Objective: Our primary objective is to equip Electron Microscopy (EM) experts with tools developed by Deep Learning (DL) experts, enabling them to create specialized solutions within their EM labs. This approach facilitates the adaptation of existing methods to new appearances of the data (for example due to new sample preparation techniques, different detectors or different modalities) based on the lab's specific needs. It allows training on lab-specific data and customization of tasks by simply providing data aligned with the lab's interests and requirements. The workflow enables the adoption of DL solutions without requiring any additional implementation effort.

Development

In deep learning for electron microscopy (EM), model development refers to the process of creating and optimizing deep learning models to address specific challenges within EM. This process is built on three key steps.

  • Data: high-quality and well-annotated datasets tailored to the lab's needs.
  • Model Training: training models by optimizing architectures and parameters.
  • Model Evaluation: evaluating their performance using task-specific metrics.
Together, these steps enable the adaptation of deep learning techniques to EM tasks, ensuring models are effective and tailored to lab-specific applications.

1. Data

High-quality data is the foundation of deep learning model development. For EM, this includes acquiring, annotating, preprocessing, and structuring data to ensure it is suitable for training and evaluating models. Properly handling data ensures model reliability and robustness.

Recognizing that expertise in data preparation primarily resides within EM labs, our workflow is designed to bridge the gap by providing EM experts with the necessary guidance from DL experts. This approach enables labs to prepare their data effectively for successful model training.

Moreover, our codebase is structured to allow model training adaptation solely through changes in data and its annotations. For instance, the number or type of classes in segmentation tasks can be easily tailored to fit specific use cases. Each use case includes a detailed guide on implementing such adaptations, ensuring flexibility and ease of use.

1.1. Data Acquisition

Data acquisition involves collecting raw electron microscopy images or datasets. This may include imaging samples under various modalities (e.g., TEM, SEM) to capture diverse features. It is critical to ensure the dataset is representative of the problem domain to improve model performance. Expertise in sample preparation, imaging modalities and data collection plays an important role and usually lies within the EM-lab.

1.2. Data Annotation

Data annotation is the process of labeling images for specific tasks such as segmentation, classification, or object detection. In the context of deep learning for electron microscopy (EM), proper annotation is crucial for training models that perform well on real-world data.

Each use case includes a detailed instruction on how to annotate data such that it can be used in a "plug-and-play" fashion. This way, we ensure that the training, validation and test data can be easily adapted to suit the specific needs of any EM lab without the need for additional code changes.

The provided use cases within this paper make use of the Computer Vision Annotation Tool (CVAT), an easy-to-use and easy-to-setup tool. For a step-by-step guide on how to get started, please refer to our Getting Started guide. Detailed use case specific instructions for EM specialists can be found in each corresponding use case.

1.3. Data Preprocessing

Data Preprocessing is an essential step in preparing data for training deep learning models. This process consists of three key stages: 1) Data Reformatting, 2) Image Enhancement, and 3) Data Augmentation.

Data Reformatting ensures that the data provided by EM specialists is compatible with the code developed by DL experts. While this step is mandatory and cannot be skipped, we have designed the workflow to abstract away the complexity of Image Enhancement and Data Augmentation, handling these steps entirely within the DL expert's domain.

Each use case includes detailed guidance for EM specialists on how to reformat common EM data formats—such as 2D or 3D `.tif` or `.mrc` files—into formats that are compatible with the training workflow. This ensures accessibility and ease of use for EM researchers, allowing them to focus on their domain expertise without requiring deep knowledge of DL techniques. Since our use cases primarily rely on the .tif format, we provide a quick guide on how to reformat data using the freely available EM tool ImageJ. Detailed instructions for these steps can be found in each use case.

1.4. Data Structuring

Data Structuring acts as the interface between DL experts and EM experts. Structuring the data in a way that is compatible with the implemented use case is essential to bridge the expertise of both domains.

Our workflow is designed to simplify this process, minimizing potential difficulties and errors. In most cases, we ask EM specialists to provide all data required for training and validation within a single file. The responsibility for splitting the data into appropriate subsets is handled at runtime by the DL experts.

Training data is used to teach the model how to make predictions, while validation data is used to evaluate the model's performance, prevent overfitting and adjust hyperparameters to improve accuracy.

As a deep learning (DL) specialist contributing to a project, we recommend implementing image enhancement methods or providing detailed documentation on freely available tools that can be used for these tasks. This ensures that all preprocessing steps are consistent and effective for the training process. Additionally, it is important to consider the reformatting of image data to ensure it can be correctly loaded into the provided code. While DL specialists handle preprocessing techniques related to training strategies (e.g., normalization, resizing, augmentation), electron microscopy (EM) specialists may need to prepare the data in formats compatible with the training pipeline.

Any preprocessing steps required by EM specialists should be clearly defined and documented in the use case to facilitate easy implementation. To ensure compatibility, we encourage the use of common formats in EM, such as 2D or 3D .tif, .mrc, and others.

2. Model Training

Model training focuses on creating and optimizing deep learning models to solve specific EM tasks. It includes configuring the training process, monitoring progress, and refining parameters to maximize performance.

2.1. Setup Logging

Logging plays a crucial role in tracking the training process, providing insights into key metrics such as loss, accuracy, and other important indicators. Well-maintained logs help optimize the model and identify potential issues, such as overfitting. Overfitting occurs when the model becomes too tailored to the training data and struggles to generalize to unseen data. It can typically be identified by analyzing training and validation curves.

In our use cases, logging is implemented using both standard output and a local logging directory at logs/current-datetime/. While there are many advanced tools available to streamline the logging process, we chose not to use them to avoid additional setup overhead for EM specialists. By utilizing standard output and a local log directory, we simplify the process without sacrificing essential information. The logs capture the following key data:

  • Hyperparameters of the run
  • Model checkpoints
  • Training/validation curves
  • Qualitative visualization of validation images
  • Results on test metrics
  • Qualitative visualization of test images
2.2. Define Hyperparameters

Hyperparameter tuning is a critical process that involves adjusting parameters to improve the performance of a deep learning model. This is typically done by running the training code multiple times with different settings and selecting the model that performs best based on its validation loss. Proper tuning of these parameters can significantly influence the model's convergence and overall performance.

The tuning process must be tailored to each specific use case, meaning it should be done every time a model is trained. This requires collaboration between DL and EM experts. To simplify the process, we use ipywidgets (a Python library for creating interactive widgets) to enable input of hyperparameters through a graphical user interface, rather than requiring manual changes in the code. DL experts will define hyperparameters to tune and provide clear explanations for each hyperparameter as well as offer practical tips to help users to select optimal settings.

2.3. Training and Validation

The training process involves iteratively feeding data into the model to minimize error, while validation ensures that the model generalizes well to unseen data. Regular validation during training helps prevent overfitting and guides optimization. This step is always implemented by the DL experts and does not require additional input of the DL expert.

3. Model Evaluation

Model evaluation assesses the trained model's performance using specific metrics to determine its effectiveness in solving the target task. This step ensures the model meets the requirements for deployment or further refinement.

3.1. Choose Model

Within each training run, the use cases are designed to automatically select the best performing model based on the validation loss. However, the use case implementation also provides the flexibility to test previously trained models by supplying the corresponding model checkpoint by the EM specialists. This feature is particularly useful for hyperparameter tuning. Again, the model checkpoint can be defined by the EM specialist via a graphical user interface based on ipywidgets. Please note that it is important that the model checkpoint is written by the same use case as the evaluation to ensure that the necessary keys match. If no checkpoint is provided by the EM specialist, the evaluation will be conducted using the most recently trained model.

3.2. Evaluation

Evaluation is guided by the expertise of the DL specialist and does not require additional input from the EM specialist. Each use case defines specific metrics tailored to the model's goals, with the DL specialist selecting key metrics and methods that enable a comprehensive assessment of the model's performance. To support the EM specialist in making an informed decision about whether the model is ready for deployment or requires further refinement, the DL specialist provides a clear explanation of what each metric or method measures and how it contributes to the evaluation process.

Inference

Inference is the process of using a thoroughly trained and tested deep learning model to make predictions on new, unseen data. It finally allows to use the model to support the analysis of EM data.

1. Define Data

To perform inference with a trained model, you first need to define the data you want the model to make predictions on. This could be a specific set of EM data that you wish to analyze. The data can be provided as a single file for prediction or as a folder containing multiple files, allowing for automatic processing of all the included data. This flexibility ensures the model can handle both individual cases and larger datasets efficiently.

2. Choose Model

The EM specialist is responsible for selecting a previously trained model for inference. This model should be based on the best-performing hyperparameters identified during training. It is essential that the model has been evaluated thoroughly according to the evaluation criteria provided by the DL expert, ensuring that the evaluation results are promising. Only models with strong performance, as indicated by the evaluation metrics, should be used for making predictions, ensuring reliable and accurate results.

2. Make Prediction

The model will be used to make predictions on the provided data. However, it's important to remember that no trained model is perfect, and human oversight remains essential. The results generated by the model should always be carefully checked for plausibility to ensure accuracy and reliability.
